# 유튜브 · X 사진 다운로더

실행할 때 **유튜브 / X** 중 하나를 선택하는 파이썬 사진 다운로더입니다.
각 플랫폼의 수집 처리, 사진, 다운로드 기록을 분리합니다.
**사진이 없는 글은 저장하지 않습니다.** 사진이 있는 글은 본문과 링크도 함께 기록합니다.

## 실행과 사용

1. **`launch.vbs`**를 더블클릭합니다. 터미널 창 없이 프로그램 화면만 열립니다.
2. **유튜브** 또는 **X**를 선택합니다.
3. 링크를 붙여넣습니다. 여러 링크는 한 줄에 하나씩 입력합니다.
4. 기본 저장 폴더, 조회할 게시글 수, 요청 간격을 정하고 **사진 받기**를 누릅니다.
5. **저장 폴더 열기**로 선택한 플랫폼의 사진을 확인합니다.

**플랫폼 바꾸기**를 누르면 선택 화면으로 돌아갑니다.
두 플랫폼의 입력한 링크는 프로그램을 닫기 전까지 각각 유지됩니다.
**잠시 멈춤 / 계속 진행**은 실행 중 대기와 재개이며, **중지**는 현재 작업을 종료합니다.
중지해도 이미 저장한 사진은 유지됩니다.

이 컴퓨터에서는 포함된 Python을 자동으로 찾아 실행합니다.
`실행.bat`도 같은 실행기로 연결됩니다. 터미널이 잠깐 나타나는 것도 피하려면 `launch.vbs`를 사용하세요.
시작 오류는 `logs/startup.log`에 기록하고 알림 창을 표시합니다.

### GitHub에서 처음 설치

1. Tkinter를 포함한 [Python](https://www.python.org/downloads/) 3.10 이상을 설치합니다.
2. 이 저장소를 다운로드하거나 복제하고, 프로그램 폴더에서 구성요소를 한 번 설치합니다.

```powershell
python -m pip install -r requirements.txt
```

3. Windows에서는 `launch.vbs`를 더블클릭합니다. macOS·Linux에서는 `python app.py`로 실행합니다.

이 GitHub 저장소에는 프로그램 소스와 설치 목록을 제공합니다.
기존 배포본의 `.deps` 폴더는 Windows 64비트 / Python 3.12용 구성요소입니다.
현재 이 컴퓨터의 프로그램에 있는 `.deps`는 그대로 사용할 수 있습니다.
로그인 쿠키·개인 설정·실행 기록·다운로드 사진은 저장소에 포함하지 않습니다.

## 입력 링크

| 선택 | 링크 | 처리 |
|---|---|---|
| 유튜브 | `youtube.com/post/게시글ID` | 해당 글의 모든 첨부 사진 |
| 유튜브 | `youtube.com/@채널명/posts` | 채널 게시글 탭을 다음 페이지까지 조회 |
| 유튜브 | `youtube.com/@채널명/community` | 이전 커뮤니티 주소도 지원 |
| 유튜브 | `youtube.com/@채널명` | 게시글 탭으로 바꾸어 조회 |
| 유튜브 | `youtube.com/channel/채널ID/posts` | 채널 ID 주소 지원 |
| 유튜브 | `youtube.com/channel/채널ID/community?lb=게시글ID` | 이전 개별 글 공유 주소 지원 |
| X | `x.com/계정/status/번호` | 해당 글의 모든 첨부 사진 |
| X | `x.com/i/web/status/번호` | 계정명 없는 개별 글 주소 지원 |
| X | `x.com/계정/media` | 로그인한 계정으로 조회 가능한 미디어 탭 |
| X | `x.com/계정` | 미디어 탭으로 바꾸어 조회 |

X의 `twitter.com`과 모바일 주소, 개별 글의 `/photo/번호` 주소도 지원합니다.
유튜브 동영상 링크, X 검색·좋아요 탭은 지원하지 않습니다.
선택한 플랫폼의 링크만 한 번에 넣으세요.

기본 수 제한은 100개이며, **0은 조회 가능한 끝까지**입니다.
유튜브에서는 사진 없는 글도 조회 수에 포함합니다. X에서는 사진이 있는 글을 셉니다.
개별 게시글 링크는 그 글 하나만 처리합니다.
0을 입력해도 서비스의 접근 제한이나 다음 페이지 오류로 조회가 끝날 수 있습니다.

## X 로그인 연결

**X 계정 미디어 탭은 로그인 쿠키 파일이 필요합니다.**
개별 공개 게시글은 로그인 없이 시도할 수 있으며, 접속 제한이 생기면 쿠키를 연결합니다.
X에서 본인 계정으로 로그인한 세션을 Netscape 형식의 `cookies.txt`로 준비하고,
프로그램의 **파일 선택…**에서 선택하세요. 자세한 형식은
[gallery-dl의 쿠키 안내](https://github.com/mikf/gallery-dl#cookies)를 참고하세요.

프로그램은 선택한 파일에서 X 관련 쿠키만 읽습니다.
브라우저 로그인 정보를 자동으로 읽지 않으며, 쿠키 파일이나 값은 다운로드 결과에 복사하지 않습니다.
**한 번 선택한 쿠키 파일은 프로그램을 다시 켜도 자동으로 연결됩니다.**
새 쿠키 파일을 선택하면 교체하고, 잘못된 파일이나 취소된 선택은 기존 정보에 영향을 주지 않습니다.
**해제**를 누르면 기억한 선택도 지웁니다. 원래 쿠키 파일은 삭제하지 않습니다.
파일을 직접 입력한 경우에는 정상적인 쿠키로 사진 받기를 시작할 때 선택을 기억합니다.
프로그램 폴더의 `settings.json`에는 쿠키 **파일 경로**를 저장하며, 쿠키 값이나 비밀번호는 담지 않습니다.
선택한 쿠키 파일은 원래 위치에 보관하세요. 파일이 사라지거나 쿠키가 만료되면 새 파일을 선택해야 합니다.
만료·로그아웃된 세션은 새 파일을 선택해야 합니다. 접근 권한이 없는 글은 받지 못합니다.
X 로그인 상태로 실제 계정 미디어 전체를 조회하는 검증에는 사용자 쿠키가 필요하며,
현재 배포본에서는 공개 단일 게시글 실다운로드와 쿠키 연결·미디어 처리 자동 검증을 수행했습니다.

## 유튜브의 추가 기능

| 기능 | 동작 |
|---|---|
| **이어서 받기** | 마지막 작업의 주소와 수 제한, 다음 페이지 위치, 진행 중인 게시글을 기록에서 읽어 재개합니다. 완료한 글은 다시 조회하지 않고, 진행 중인 글에서 받은 사진은 건너뜁니다. |
| **실패한 사진 재시도** | 채널을 새로 조회하지 않고 저장 기록의 실패·중지·대기·누락 사진만 다시 받습니다. |
| **요청 간격 조절 / 잠시 멈춤** | 모든 조회·사진 요청 사이에 설정한 시간만큼 기다립니다. 실행 중 대기했다가 다시 진행할 수 있습니다. 기본 간격은 1초입니다. |
| **저장 사진 검사** | 파일 존재, 사진 디코딩, 모든 애니메이션 프레임, 저장 당시의 SHA-256을 검사합니다. 최대 크기 대조와 자동복구를 선택할 수 있습니다. |

이어받기는 해당 유튜브 저장 폴더의 **마지막 사진 받기 작업 한 개**를 대상으로 합니다.
새로 **사진 받기**를 누르면 이어받기 기록이 새 작업으로 교체됩니다.
모두 조회한 작업에서 사진만 실패했다면 **실패한 사진 재시도**를 사용하세요.
오래된 다음 페이지 정보가 만료되면 다시 사진 받기를 실행해야 할 수 있습니다.
이 경우 이미 저장한 정상 사진은 건너뜁니다.

재시도와 검사는 링크를 입력하지 않아도 됩니다.
같은 기본 폴더에 남아 있는 이전 버전의 유튜브 저장 기록도 검사·재시도할 수 있으며,
기존 사진의 폴더 위치는 바꾸지 않습니다.

### 최대 크기 대조와 복구

**검사 시 서버 최대 크기와 대조**를 선택하면 유튜브 이미지 서버의 `s0` 파일을 다시 받아
저장 사진과 해시·가로·세로 크기를 비교합니다. 따라서 인터넷 접속과 추가 다운로드가 필요합니다.
정확히 일치, 더 작은 사진, 파일 내용 차이, 대조 불가를 구분해 `post.json`에 기록합니다.
서버가 재압축하거나 파일을 변경하면 크기가 같아도 내용 차이가 나타날 수 있습니다.
**업로드하기 전 작성자가 가진 원본 파일과 동일하다는 보증은 아닙니다.**

**문제 사진 자동복구**는 기본으로 꺼져 있습니다.
켜면 손상·누락 사진을 다시 받고, 서버 최대 크기와 다른 사진은 최대 크기로 교체합니다.
기존 파일이 있으면 게시글 폴더 안의 `backups`에 먼저 보관합니다.
서버 요청에 실패하면 기존 사진은 유지하며 대조 불가로 표시합니다.
인터넷 대조를 끄면 파일 손상·변경·누락만 검사합니다.

## 저장 구조

기본 저장 위치는 프로그램 폴더의 `downloads`입니다.
사용자가 다른 기본 폴더를 지정해도 그 안에 `YouTube`와 `X`를 나누어 사용합니다.

```text
downloads/
  YouTube/
    작성자__게시글ID/
      image_01_고유번호.png
      image_02_고유번호.jpg
      post.txt
      post.json
      backups/              # 기존 파일을 복구·교체할 때 생성
    checkpoint.json         # 마지막 유튜브 작업의 이어받기 위치
    run_날짜_시간.json
    retry_날짜_시간.json
    inspect_날짜_시간.json
  X/
    계정__게시글번호/
      image_01_고유번호.jpg
      post.txt
      post.json
    run_날짜_시간.json
```

사진 형식에 맞게 `.jpg`, `.png`, `.gif`, `.webp`, `.avif`로 저장합니다.
유튜브는 `s0`, X는 `name=orig`를 먼저 요청하고 실패하면 제공되는 다른 크기를 시도합니다.
저장 결과에 요청한 주소, 크기, 해시, 실제 받은 품질을 기록합니다.
같은 게시글을 다시 실행하면 정상적인 기존 사진은 건너뛰고, 본문과 저장 기록을 갱신합니다.
프로필 사진, 영상 미리보기, 동영상, 댓글은 받지 않습니다. 사진 한 장의 제한은 100 MiB입니다.
같은 폴더를 대상으로 프로그램 여러 개를 동시에 실행하지 마세요.

## 명령줄과 다른 프로그램에 연결

```powershell
python app.py
python app.py --platform youtube "실제 유튜브 게시글 링크" -o "D:\사진"
python app.py --platform youtube "https://www.youtube.com/@YouTube/posts" --limit 0 --interval 2
python app.py --platform youtube --action resume -o "D:\사진"
python app.py --platform youtube --action retry -o "D:\사진"
python app.py --platform youtube --action inspect -o "D:\사진" --repair
python app.py --platform youtube --action inspect -o "D:\사진" --local-check
python app.py --platform x "실제 X 게시글 링크" -o "D:\사진"
python app.py --platform x "https://x.com/계정/media" --cookies "D:\비공개\cookies.txt" --limit 0
```

UI 없이 사용할 때는 `pipelines.run()`을 호출합니다.
`platform`은 `youtube` 또는 `x`, `operation`은 `download`, `resume`, `retry`, `inspect`입니다.
추가 작업 세 가지는 유튜브 전용입니다. `RunControl`로 중지·대기·요청 간격을 제어하고,
`log` 콜백으로 진행 문구를 받습니다. `Report`에 사진 수, 오류, 결과 기록 위치를 반환합니다.
유튜브 수집 코드는 `downloader.py`, X 수집 코드는 `x_downloader.py`,
유튜브 재시도·검사는 `youtube_jobs.py`에 있어 다른 프로그램의 UI와 연결할 수 있습니다.

종료 코드는 정상 0, 오류나 사진 실패 1, 중지 130입니다.
프로그램은 유튜브와 X의 웹 정보를 사용하므로 서비스 구조 변경이나 접속 제한으로 수정이 필요할 수 있습니다.
유튜브 회원 전용·비공개·삭제된 게시글은 지원하지 않습니다.

## 검증 및 구성요소

```powershell
python -m unittest discover -s tests -v
```

회귀 검증은 외부 접속 없이 이어받기, 사진 실패 재시도, 검사·원본 크기 대조·복구,
플랫폼별 저장 분리, X 주소·앨범·쿠키 처리와 쿠키 파일 선택의 유지·교체·해제를 확인합니다.
공개 유튜브 게시글의 사진 5장과 공개 X 게시글의 사진 1장을 실제로 저장했고,
유튜브 사진 5장의 서버 최대 크기 대조도 확인했습니다.

X 수집은 [gallery-dl](https://github.com/mikf/gallery-dl), 사진 디코딩은
[Pillow](https://pillow.readthedocs.io/en/stable/)를 사용합니다.
동봉된 구성요소의 출처와 라이선스는 `THIRD_PARTY_NOTICES.txt`와 `.deps`의 라이선스 파일에 있습니다.
